# Xournal Studio (Xournal++ Fork) Work Log

## Repository

- Fork: https://github.com/robertkleinschuster/xournalpp
- Upstream: https://github.com/xournalpp/xournalpp
- Local checkout: C:\Users\rober\xournalpp
- Branch: master
- Use case: Xournal++ on a Windows convertible for university.

## Fork-specific behavior

- Keep the fork identity and configuration directory separate from upstream so both installations can run side by side.
- The fork is named "Xournal Studio": window title, About dialog, exe version info, installation folder and Start menu entry (install-fork.ps1 removes the old "Xournal++ Fork" installation). Its icon (ui/pixmaps/com.github.xournalpp.xournalpp.svg, also the .exe icon) is the Xournal++ icon on a blue grid tile. The config folder stays xournalpp-fork so existing settings keep working.
- Preserve the touch-sequence reset on window deactivation. It prevents stale touch state from breaking touchscreen scroll and pinch zoom.
- Use graph paper as the default for new documents.
- A PDF without its .xopp opens read-only (no files are created) with an info bar; only its "Enable Editing" button creates the .xopp next to the PDF or opens an existing one. Read-only is enforced in ActionDatabase (EDITING_ACTIONS), XojPageView's press handlers, PageBackgroundChangeController, drag and drop, and Control::close discards. The annotated PDF is only exported once the document has annotations (AnnotationFiles::hasAnnotations) or an export already exists.
- The "Copy PDF Area" tool (TOOL_COPY_PDF_AREA, in the PDF tool dropdown and the Tools menu) copies the rectangle drawn on a PDF page as soon as it is released and shows it for a moment (PdfFloatingToolbox::copyFinishedArea); the floating toolbox has no copy-area button. Copying renders the area into a one-page vector PDF stored in a TexImage without LaTeX source (PdfElemSelection::createAreaElement) and puts it on the clipboard like a copied selection (ClipboardHandler::copyElement, EditSelection::serializeElement). That PDF contains the whole page's content clipped to the area, so above 256 KB (e.g. scanned pages) a 300-DPI PNG Image is used instead if it is less than half the size. Other applications get the area's text and PNG/SVG images, rendered only when requested. TexImages without LaTeX source (TexImage::hasLatexSource) are not opened or replaced by the LaTeX editor. A finalized area selection shows the area lightly with an outline and the text lines that marking applies to. Areas copied since the portal change also show the PDF page itself, exactly at any zoom (`PdfPortal` on `RectangularElement`; the TexImage/Image above stays as their snapshot): copying extracts the page with QPDF as a one-page PDF from the PDF as shown, i.e. its bytes in memory (`XojPdfDocument::getData`, else the file; `PdfPortalStore::extractPage`, key = hash of it, links/beads removed so no other pages come along). The .xopp stores only `portal`/`portal-area` attributes, which upstream ignores silently (unknown tags would raise load errors there, unknown attributes do not); the pages live once each in `<name>.portals.pdf` next to it (`AnnotationFiles::portalsPdf`, page dictionary key `/XournalStudioPortalKey`), never in other PDFs: a separate file so git stores pages once instead of with every commit of the gzip .xopp. `SaveHandler::saveTo` writes it after the .xopp only when the set of pages changed (removed with the last area; kept if pages were missing/unreadable at load), not for the .xoj export nor for recovery copies (autosave, crash: `setWritesPortalFile(false)`). Missing file → snapshots. On the clipboard the elements are serialized exactly like upstream and the portals follow as an appendix (`PdfPortal::serializeAppendix`/`readAppendix`), so upstream and the fork paste each other's data. It is renamed/moved/discarded with the document, always deleted with it, and not shown in the project explorer. Older areas are untouched.
- Touch: StuckTouchIdFix works around GDK 3 (win32) ignoring a reused touch id forever after a cancelled/low-confidence touch (symptom: every gesture needs one finger more). Touchscreen and touchpad swipes share ScrollMomentum, so both glide on; a pinch does not. A quick flick (under 0.3 s) in the same direction while the document still glides adds to its speed, up to 12000 px/s (`ScrollMomentum::combinedSpeed`), so long documents are crossed with a few flicks. InputSafety (first in the GDK event handler) ends a stale implicit pointer grab: a touch/pen press that GDK delivers to a window it does not lie in (seen after a tap at the left screen edge left a press on the toolbar without release, after which all touches went to the toolbar for 20 s) is dropped and the pointer ungrabbed. It also hides tooltips that GTK maps while neither the pen hovers nor the mouse was used last (they flashed after the pen left and after touches).
- Saving writes "<name>.xopp~" and only replaces the .xopp once it is complete (SaveHandler::saveTo), so a failed save or crash keeps the previous version; there is no separate backup copy. When switching documents in the project explorer fails to save the current one, it stays open (DocumentAutoSaver::saveNow reports the result). Documents are gzip-compressed with libdeflate when available (GzOutputStream, about 3x faster than zlib). `PowerEvents` (Windows: lid closed, screen off, suspend → Standby; screen on/resume → Wake; the state reported right after registering is ignored) makes DocumentAutoSaver save at once on Standby, also ending text editing or a selection, and ConvertibleSupport reset touch sequences, close popups and re-check the tablet mode on Wake. Automatic saves (focus loss, switching documents) skip files loaded with errors or a newer file format (Control::isAutoSaveAllowed) until the user saves them. An explicit save always writes the file, like upstream; an export that was up to date stays marked up to date.
- The annotated PDF is exported from a deep copy of the document on its own thread (AnnotationExporter), so the window is not blocked; requests during a running export wait for it. Its time is dominated by cairo_show_page, not by QPDF. test/benchmarks/ownFilesBenchmarkTest.cpp measures load, save and export of real documents listed in XOPP_BENCHMARK_FILES.
- Git commands run in a job object and are terminated with their helpers after a timeout (2 min background fetch, 10 min otherwise); a pull failure is only reported as a conflict when git reports one. .xopp headers read by the explorer are cached by exact file stamp (AnnotationFiles cachedXoppTag).
- The sidebar keeps the tab the user chose while it has content (it does not jump to the project explorer). At startup the explorer's last document is only reopened with the upstream "Autoload most recent" setting; exported/source PDFs only redirect to their .xopp with "Autoload pdf.xoj". Renaming a PDF in the explorer relinks the document annotating it (AnnotationFiles::relinkSourcePdf). The explorer search runs on a worker thread.
- The page and layer previews in the sidebar are one column of miniatures scaled to the sidebar width (`SidebarPreviewBase::newWidth` sets the zoom from the widest page, `SidebarLayout` centers them); a wider sidebar gives larger miniatures instead of more columns.
- Pages are reordered by dragging their miniature in the page preview sidebar (`PageReorderGesture`, capture-phase `GtkGestureDrag` on the miniature container): mouse/pen after 12 px, touch after a 0.4 s hold, otherwise the finger scrolls the list. A line marks the drop position, the list scrolls near its edges, the move is one undo step (`MovePageUndoAction`).
- "Journal → Insert Pages…" (`InsertPagesDialog`) replaces upstream's "Append New PDF Pages" (whose action now opens it): thumbnails of the document's own PDF (pages not in the document preselected) or of another PDF; tap toggles a page; they go at the beginning, after the current page or at the end. Own pages are inserted without changing the background PDF. For another PDF: A document has one background PDF, so `PdfCombiner` (QPDF) appends the pages to a combined copy: the companion `<name>.pages.pdf` (`AnnotationFiles::companionPdf`; not shown in the project explorer, also as the nested source PDF of its document, where the original PDF named like the document is shown instead); a PDF marked `/XournalStudioCombined` is reused and rewritten, also an older `<name> (combined).pdf`. The source PDF is never modified. The combined PDF is loaded from memory so the old file can be replaced on Windows; undo removes the pages and restores the previous background PDF. Documents with an attached PDF are not supported. Companion files (`<name>.pages.pdf`, `<name>.portals.pdf`) sit next to the document without a leading dot and are not hidden, so the Windows Explorer shows them next to it and that the document needs them; ".<name>.pages.pdf" of earlier versions is still recognized and its hidden attribute removed when loaded. Without a leading dot, a file only counts as a companion while "<name>.xopp" exists next to it (`isCompanionPdf`/`isPortalsPdf`), so a PDF of the user named like that is not hidden.
- Images in the project explorer are active entries: a tap (or "Insert Image…" in their context menu) shows them in `ImageCropDialog` (drag corners/edges, move the frame, or draw a new one; touch grabs from 28 px) and inserts the chosen part on the current page like a pasted image (`ImageHandler::insertCroppedFromFile` -> `Control::pasteImage`). Uncropped images keep the file's bytes; cropped JPEGs are stored as JPEG (quality 92), others as PNG. The upstream image tool (file chooser) has no cropping. Other files that are neither documents nor executable (`isExecutable`: programs, scripts, shortcuts are never started by a tap in the git-synced folder) open in their Windows default app on tap or via "Open in Default App".
- Project explorer: "Discard Changes…" restores a file or the changed files of a document group (`AnnotationFiles::groupFiles`: the document, the background PDF it owns per `ownsSourcePdf` – named like it or its combined PDF – and its export) with `git restore --source=HEAD --staged --worktree`; untracked files are not offered. Deleting a document with group files asks "Only the Document" / "Delete All". Before such file operations the open document is closed and replaced by an empty one (`Control::releaseDocumentFiles`), because `Document::clearDocument` keeps the poppler document, which keeps the PDF file locked on Windows.
- Tasks: the sidebar tab "Tasks" (second tab, `TasksSidebar`) collects all `todo.txt` and `*.todo.txt` files of the project folder (`TaskFiles::find`, hidden folders skipped) in groups Overdue/Today/Upcoming/No date/Later/Completed. The check boxes are not activatable cell renderers (GTK 3 activates cells only on mouse presses); a tap or click on the check box column completes the task through `row-activated`. Files are edited line by line and re-read before each change (`TaskFiles::replaceLine`), so edits from other todo.txt apps and Git pulls are kept; unknown tags stay untouched (`TodoTxt::parse`/`format` round-trip). Format: standard todo.txt plus `due:YYYY-MM-DD`, `time:HH:MM`, `t:` (start), `rec:` (Simpletask syntax; the edit dialog writes strict `+1w` etc. so lectures keep their weekday), `remind:` (absolute `YYYY-MM-DDTHH:MM` or relative `-30m/-2h/-1d`), `doc:path#pN` (relative to the task file, `%20` for spaces). Quick add parses German/English dates ("morgen 14:00", "bis Freitag", "5.11.", "in 3 Tagen"). New tasks go to the nearest `todo.txt` up from the current document, else the project root. "Journal → New Task for This Page" (Ctrl+Shift+K) links the task to the page. Reminders while the app runs: at the due time or the `remind:` times, checked every 30 s (catches standby), plus one daily overview from 08:00 (state in `tasks.ini` in the config folder); shown by `TaskNotifier` as notification area balloons (Windows shows them as toasts; impossible from another desktop).
- Scratchpad (`ScratchpadDrawer`, "View → Scratchpad", Ctrl+Shift+N): one sheet for all documents, `Schmierzettel.xopp` in the project folder (else the config folder), so the git sync commits it. A pull tab at the top center of the canvas (in an overlay around the canvas, `MainWindow::getCanvasOverlay`; at the bottom the Windows taskbar was in the way) pulls the sheet down from the top on tap or drag. GtkOverlay does not clip overlay children to the canvas and keeps the window of a child that is only not child-visible: the sheet sits in a `GtkLayout` (`clip`, allocated to the visible height, scrolled so the panel's lower edge shows) and closed sheet and hidden tab are hidden with `gtk_widget_set_visible`; otherwise their windows covered the read-only bar above the canvas and swallowed its clicks. It moves like an iOS sheet: on release it snaps to the detent (closed, half, full height minus `DOCUMENT_STRIP`) nearest to where its velocity would carry it (at most one detent further), with a damped spring that keeps the release velocity and overshoots slightly; pulled beyond the full height it follows with rubber-band resistance. A tap opens it to the last detent (kept as a share of the canvas height) or closes it. The sheet has its own small editor, not the document's tools: pen and mouse write with the pen tool's color/width and pressure, the pen's eraser end, the barrel/right button or the eraser button remove whole strokes, a finger scrolls (`ScrollMomentum`; touches right after pen input are ignored as a resting palm), its own undo/redo, "Clear", and "Open as Document" (all tools; the tab is hidden while it is the open document). The A4-landscape-wide page grows downwards while writing. It is written 1.5 s after a change, on closing, on standby, before a git sync (and reloaded after it if the pull changed it), and on quit; the file is created with the first stroke.
- PDF reading (`XojPageView::followPdfLinkAt`/`followPdfLink`): a mouse click follows a PDF link directly (internal links via `ScrollHandler::scrollToLinkDest`, which records it for Back; URIs in the browser), touch and pen get the confirming popover; the mouse shows a hand over links (`hasPdfLinkAt` with the link areas cached per page, `XournalppCursor::setOverPdfLink`) where a click would follow them. Links that lead nowhere (other files, unknown actions) are ignored instead of offering a dead button; named actions (beamer navigation: NextPage, PrevPage, FirstPage, LastPage, GoBack, GoForward, Find) run the matching action (`LinkDestination::getNamedAction`). Releasing a PDF text/area selection does not open a link popover. Link popovers are destroyed when closed. Search (`SearchBar`): typing finds the text from the page shown onwards (also on later pages, jumping to the first match), Next/Previous continue from the page shown, reopening the bar selects and searches the previous text again; matching ignores diacritics and finds phrases across line breaks (`PopplerGlibPage::findText`, continuation parts of a match are not counted). A single PDF/.xopp/.xoj dropped on the window opens instead of being pasted (`MainWindow::dragDataRecived`). While a PDF is read-only, the toolbar tool becomes PDF text selection unless it is usable read-only (`Control::isUsableReadOnly`), so mouse and pen select text and follow links; the previous tool comes back with editing and is what is saved in the settings.
- A short finger tap (one finger, under 12 px movement, under 500 ms, not one that only stopped a gliding scroll) on a PDF link shows the link popover whatever tool is active (`TouchInputHandler::handleTap` -> `XojPageView::showPdfLinkAt`). Fingers otherwise only scroll and zoom.
- On Windows the main window turns off pen flicks, press-and-hold and pen feedback (PenFeedbackFix). Ctrl + two-finger touchpad swipe zooms. Lua functions that modify the document raise an error while it is read-only.
- Windows with a native title bar (dialogs) get the dark Windows title bar while GTK prefers the dark theme (`DarkTitleBars`, DWMWA_USE_IMMERSIVE_DARK_MODE on realize).
- UI for a right-handed convertible user: the menu bar sits in a dark GTK header bar (MainWindow::moveMenubarToTitleBar) and stays visible in tablet mode (the pen reaches every function through it); nothing interactive at the right edge (e.g. the read-only bar's button is on the left). ConvertibleSupport hides the sidebar in portrait and opens the touch keyboard for text fields tapped in tablet mode. The sidebar separator is wide and draggable by touch (TouchPanedHandle). The Insert page toolbar button has no dropdown; the PDF tool dropdown defaults to Copy PDF Area. DocumentAutoSaver also saves after 30 s without input; the explorer pauses git polling in the background. Normal and fullscreen view share one sidebar state (Control::setShowSidebar writes both view modes), and switching view modes updates the sidebar/toolbar/menubar toggle states. Deleting a page (toolbar, menu, page sidebar) asks for confirmation first (Control::askDeletePage).
- Switching documents is meant to be instant (e.g. between an exercise and the lecture notes): the last `DocumentCache::MAX_ENTRIES` documents stay in memory with their rendered PDF pages and the images of the visible pages (`KeptRendering`), and are reused only while their files are unchanged on disk (`AnnotationFiles::fileStamp` taken when loaded or saved; git, other programs and explorer operations cause a reload). Each document reopens at its exact view: zoom (or fit mode) and the position within the page are stored on closing (`MetadataManager::storeViewPosition`, `offset=`/`fit=` lines, in the data folder) and applied before the first frame, also after a restart (once the window knows its screen DPI: `Control::applyPendingViewPosition` from the configure event), with rendering held during the swap and the current page rendered first. PDF caches (view and sidebar previews) are only replaced with the scheduler locked, which render and preview jobs hold while running. Switching does not wait for the PDF export (it runs on a copy in the background, queued in `AnnotationExporter`); quitting does. PDFs are read into memory, so poppler keeps no file open (on Windows that would block git and the explorer from replacing them).
- Smooth scrolling and zooming: the UI thread never waits for a PDF page being rendered (`PdfCache::evictAllExcept` skips while the render lock is held; it used to stall page changes and the 5 s cleanup timer for up to 0.6 s at high zoom), pages are drawn at whole-pixel scroll positions (`gtk_xournal_draw_origin`; fractional ones forced a slow bilinear blend of every page), and page images shown scaled while zooming use the bilinear filter (the default shrank them with a convolution, up to 90 ms per frame).
- Lines and shapes drawn with the pen (shape tools, spline, arrow heads, geometry tools: `InputHandler::createShapeStroke`/`applyTypicalPenPressure`) get the width handwriting typically has, not the full width only the strongest pressure reaches: `Settings::typicalPenPressure`, the share of the pen width, is learned from written strokes (moving average over about 20 strokes of 10+ points, default 0.6, saved on exit). Recognized shapes keep the average pressure of their own stroke. A recognized line runs exactly from where the pen landed to where it lifted (`ShapeRecognizer::tryLine`), not between the ends of a line fitted through all points; hooks at the ends (end segments under 10 % of the length, or end points over 2.5 pt off the line within that share) are cut off, and it snaps level/upright only if the end moves at most 3 pt.
- Multimodal input is built from shared pieces, so every area behaves the same; use them instead of per-widget code. `gui/InputModality.h`: `modalityOf(event|gesture)` (the physical device; `gdk_event_get_device`/`gtk_gesture_get_device` are the logical pointer, always a mouse on Windows) and the one set of tolerances: `TOUCH_SLOP` 12 px, `TOUCH_HOLD_MS` 400 (taps are shorter, holds open menus or start drags), `DRAG_THRESHOLD` 12 px. `gui/ContextMenuTrigger`: every context menu opens by right click (mouse, pen barrel button), touch long press (opens while the finger still holds; the pen has none, it holds still while writing) and Menu key/Shift+F10. Menus are popovers pointing at the requested position (`ContextMenuTrigger::popup` with a .ui GMenuModel or a `ContextMenu` built in code; `rowOf` for tree views): unlike a GtkMenu, a popover ignores the release of a press that began before it opened, so lifting the finger neither chooses an entry nor closes it. Used by the explorer, task list, page and layer previews. Context menus only hold actions for their entry; folder-wide explorer actions (collapse, refresh, open/close folder) are in the "⋯" button next to the search (also the menu outside of the entries). The sidebar shows the open tab's short title next to the tab buttons (`AbstractSidebarPage::getTitle`; tooltips do not show for touch and pen). Explorer names are shortened in the middle. The canvas deliberately has no context menu (the user finds it irritating there; right click and the barrel buttons switch tools). The mouse (also the touchpad) never draws: while the toolbar tool puts ink on the page (pen, highlighter, shape tools), the left button and every button set to "don't change" use the left button's tool, by default Select Object with the normal arrow (`MouseInputHandler::changeTool`; the pen keeps the toolbar tool, as with the eraser button); other toolbar tools (text, PDF text, eraser, ...) work with the mouse as usual. A saved left-button "don't change" (or the rectangle selection of the first version) becomes Select Object on load (`Settings::loadButtonConfig`). A click that selects nothing follows a PDF link there. Where a hold already means dragging (page previews, `PageReorderGesture`), lifting the finger without moving opens the menu (`TouchHold::HandledElsewhere`). Windows does not synthesize right clicks from touch here (GTK gets touch events; PenFeedbackFix disables press-and-hold). When the tablet mode or the orientation changes, open menus and popovers are closed (`closeTransientPopups`; dialogs stay) and a touch keyboard we opened is closed on leaving tablet mode. In tablet mode a screen-wide stylesheet (ConvertibleSupport `TABLET_CSS`) enlarges toolbar buttons, sidebar tabs, menu/popover entries and tree rows. The explorer's file icons are pre-rendered pixbufs (GFileIcon SVGs were rendered again per row and frame).
- Git sync: background saves pause during a sync (DocumentAutoSaver::setPaused), the commit is limited to the project folder ("commit -- ." from it), and reloading after the pull compares exact file stamps (AnnotationFiles::fileStamp). Deleting the open document in the explorer discards it (force close). The Windows wrapper starts xournalpp with CreateProcessW instead of GSubprocess. Touch taps while a menu bar menu is open are handled by TouchButtonFix (switch/close menus). Parallel cairo rendering of the PDF export was tried and brought no measurable gain.
- Keep UI changes focused: a project-folder browser in the existing sidebar and persistent document tabs. The startup recent-documents overlay has been removed. Git support stays minimal: status colors in the explorer tree (green new, blue modified) and a single sync button (commit, pull --rebase, push) shown only for git repositories. Do not add further Git UI or replace the normal document view.

## Windows build

- The local MSYS2/UCRT64 build is configured in build/.
- Run windows-setup/build-local.ps1 for an incremental build, package, and side-by-side installation.
- Use -SkipInstall if the fork is running; install-fork.ps1 refuses to overwrite files locked by a running process.
- The manually triggered CI workflow is .github/workflows/fork-windows-build.yml.
- Releases: pushing a tag `xournal-studio-v*` (or running the workflow with `release_tag`) builds the installer and a portable ZIP and publishes both as a GitHub release. Before publishing, the packaged program exports a PDF with only Windows on PATH (smoke test in make-installer-windows.yml).
- The installer must run on a plain Windows 11 without MSYS2: package.sh copies the imports of every bundled .exe/.dll from MSYS2 until nothing is missing, bundles `etc/fonts` (fontconfig finds no fonts without it), and fails via check-dependencies.sh if a DLL is neither bundled nor part of Windows (Visual C++ runtime DLLs count as missing).
